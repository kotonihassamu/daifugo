# 16組大富豪オンライン

友達同士が各自のスマホのブラウザから部屋URLで集まり、2〜8人で大富豪を遊べるWebアプリです。
サーバーは持たず、**GitHub Pages(静的配信)+ Firebase Realtime Database / 匿名認証(無料枠)** だけで動きます。
ビルド不要の素のES Modulesで書いているので、ファイルをそのまま配信すれば動きます。

- アプリのインストール・アカウント登録なし。名前を入れるだけで参加
- 部屋URLの共有(スマホの共有シート)/ 4桁コードで参加
- リロード・回線切れでも同じ席・同じ手札に復帰(匿名認証のIDで識別)
- カードはすべてSVGで描画(画像ファイルなし)。配札・出す・場流れ・革命などの演出あり
- 縦向きはテーブルを真上から見た配置、横向きは楕円テーブル

## まず手元で試す(Firebase不要のデモモード)

```sh
python3 -m http.server 8080
# → http://localhost:8080/?local=1 を開く
```

`js/config.js` が未設定のあいだは自動でデモモードになります。デモモードでは **同じブラウザのタブ同士** が別のプレイヤーとして同期するので、タブを2〜3個開いて部屋を作る/参加すると1台で動作確認できます。

## 公開手順

### 1. Firebase の準備(無料の Spark プランでOK)

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成
2. **Authentication** → 「始める」→ ログイン方法で **匿名** を有効にする
3. **Realtime Database** → 「データベースを作成」(ロケーションは `asia-southeast1` など)。ロックモードで作成してよい
4. Realtime Database の **ルール** タブに [`database.rules.json`](database.rules.json) の中身を貼り付けて公開
   (Firebase CLI を使う場合は `npx firebase deploy --only database`)
5. プロジェクトの設定 → マイアプリ → **ウェブアプリを追加** し、表示された設定値を [`js/config.js`](js/config.js) に貼り付ける
   (`apiKey` などは公開されても問題ない値です。アクセス制御はルールで行います)
6. Authentication → 設定 → **承認済みドメイン** に `<GitHubユーザー名>.github.io` を追加

### 2. GitHub Pages で公開

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
2. `main` ブランチに push すると [`.github/workflows/pages.yml`](.github/workflows/pages.yml) がテストを実行してから公開します
3. 公開URL:`https://<GitHubユーザー名>.github.io/daifugo/`

Firebase Hosting で配信したい場合は `npx firebase deploy --only hosting` でも公開できます([`firebase.json`](firebase.json) 設定済み)。

## 遊び方

1. トップで「部屋を作る」→ 名前を入れると部屋ができ、4桁コードが表示されます
2. 「招待URLを送る」でLINEなどに共有。もらった人はURLを開いて名前を入れるだけ(コード入力でも可)
3. 待合室にいる人は全員参加になります(見るだけの人は「観戦にする」)。ホストは人数を確認して「ゲーム開始」(参加順=席順・時計回り)
4. 手札はタップで選択、指を横に滑らせると連続選択。出せる組み合わせのときだけ「出す」が押せます
5. ゲームが終わると全員が待合室に戻り、結果が表示されます。メンバーはそのまま次のゲームに引き継がれます
6. 待合室では途中参加・退出が自由です。ゲーム中に入ってきた人は観戦になり、次の待合室で参加できます
7. 接続が切れた人も、同じURLを開けば待合室(またはゲーム中なら自分の席)に戻れます。戻ってこない人は、ホストが待合室で「外す」を押せます

切断中の人の手番では、ホストに「代わりにパス」「代わりにスキップ」などのボタンが出ます。続けられないときは、ホストがメニューの「ゲームを中止して待合室へ」で待合室に戻せます(ポイントは付きません)。ホストがいなくなったら、ほかの人が「ホストを引き継ぐ」を押せます。

## 構成

```
index.html            画面の入れ物
css/style.css         見た目(縦向き/横向き、演出)
js/cards.js           カード表記・強さ・並び替え
js/rules.js           ルール判定(出せる形・強さ・縛り・効果)※純粋関数
js/engine.js          ゲーム進行(配札・手番・効果の処理順・上がり・都落ち・交換)※純粋関数
js/room.js            部屋の作成/参加/同期、操作の送信、受け箱の取り込みなどの自動処理
js/backend-firebase.js  Firebase(匿名認証 + Realtime Database)
js/backend-local.js     デモ用(localStorage + BroadcastChannel でタブ間同期)
js/ui/*.js            カードSVG・ゲーム画面・演出・効果音
database.rules.json   セキュリティルール
tests/                ルール/進行のテスト、エミュレータでの通し試験
```

### 同期の仕組み

- 部屋の公開情報(`rooms/<id>`)と各自の手札(`hands/<id>/<uid>`)を分け、手札は本人しか読めません
- ホスト端末は配札だけを担当。手の合法判定と場の更新は、操作した本人の端末が行います
- 場の更新は `game.seq` を1ずつ増やす **楽観的排他** で行い、ルールで「seq が+1であること」「手番(または効果の処理担当)が自分であること」を検査します。手札と場は1回のマルチパス更新で同時に書くので、片方だけ反映されることはありません
- 他人の手札を変える効果は、本人以外が手札に触れない形で処理します
  - **7渡し・カード交換**:受け取る人だけが読める受け箱(`inbox/<id>/<uid>`)に書き、受け取った本人の端末が手札に取り込む
  - **12ボンバー**:場に「指定された数字」を書き、各自の端末が自分の手札から消して枚数を更新する。全員の反映が済むまで進行を止め、「○○さんの反映待ち」と表示する
- 最終操作から24時間たった部屋は、次にだれかがアプリを開いたときに削除されます

## 仕様で決めきれていなかった点の扱い

要件定義書の「仮案」はそのまま採用しました。そのほか、実装で決めたことは次のとおりです。

| 項目 | 扱い |
| --- | --- |
| パス | 回数の制限なし(出せるカードがあってもパスできる) |
| 階段の革命 | 同じマークの4枚以上の階段のみ。マークが混ざった階段は出せるが革命は起きない(ジョーカーはそのマークの代わりになる) |
| 5スキップで飛ばされた手番 | パス扱いにしない |
| 親(場が空)のパス | できない。親が切断中ならホストの「代わりにパス」で次の人に親が移る |
| 手番が「最後に出した人」に戻ったとき | 5スキップで一周した場合も含め、場が流れてその人から |
| ジョーカーとマーク縛り | ジョーカーはどのマークにもなれるものとして縛りの成立も判定する。単体ジョーカーでは縛りは成立しない |
| 数字縛り中の単体ジョーカー | 出せる(常に最強)。返せるのはスペ3のみ |
| 11バック中の11バック | もう一度逆転する(元に戻る) |
| 同じ数字5枚(4枚+ジョーカー) | 出せない(2〜4枚のみ) |
| 12ボンバーで2つ以上指定 | 違う数字を指定する |
| 最後の1枚がQで上がった場合 | 上がった後も12ボンバーの指定はする |
| 切断中の人の選択待ち | ホストは手札を見られないため、7渡し・10捨て・ボンバー指定・交換の返却は「スキップ」(効果なし)で進める |
| ゲーム開始時の参加者 | 待合室にいる接続中の人(「観戦にする」を選んだ人を除く。ホストは常に参加)を、参加順に最大8人 |
| カード交換・先手・都落ち | 直前のゲームの結果だけで決める(中止したゲームの次は交換なし) |
| 1ゲーム目のダイヤの3 | 配る枚数の多い「最初の人」がダイヤの3を持つように配る(2人のときは配られないことがあり、その場合は一番弱いカードを持つ人が先手) |

## 割り切っている点

- 手の合法性は出した本人の端末で判定するため、改造したブラウザなら不正な手を書き込めます(友達同士の利用前提)
- ホストは配札の瞬間に全員の手札をメモリ上で知り得ます
- ルールの部屋ごとの ON/OFF、定型スタンプ、時間制限、CPUプレイヤーは未実装(判定はルールごとに部品化してあります)
